| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1  | Клиент видит список депозитов с актуальными ставками и может отправлять заявку                               |              |
| F2  | Сайт создаёт заявку в кол-центр                               |              |
| F3  | Менеджер кол-центра видит заявку и звонит клиенту                               |              |
| F4  | Клиент видит персонифицированные предложения по депозитам                              |              |
| F5  | Клиент подаёт заявку по конкретному предложению и подтверждает через СМС                              |              |
| F6  | Заявка на создание депозита падает в АБС и менеджер вручную её обрабатывает                             | MVP             |
| F7  | Ставки к депозитам хранятся в XLS и к ним имеют доступ бэк-офис кредитования и депозитов                              |              |
| F7  | Менеджер отдела депозитов может согласовать персональную ставку, после подтверждения кредитного менеджера                 | Требуется механизм согласования в системе. Сейчас работает через почту             |
| U   | Удобство использования (Usability) |              |
| U1  | Общий корпоративный дизайн                               |              |
| U2  | Максимально удобный интерфейс для клиента                               | Адаптивная вёрстка, чтобы можно было использовать на разных устройствах (ПК, мобильные)             |
| R   | Надёжность (Reliability)           |              |
| R1  | Доступность 24*7                                | 2 ЦОД. Репликация данных, общий шлюз с возможностью ручного переключения             |
| R2  | Аптайм 99.9%                                | Автоматизированные обновления. Docker, Kubernetes-helm             |
| R3  | При недоступности АБС\кол центра, заявки должны сохраняться в очереди                             | Ставить заявки через брокер             |
| P   | Производительность (Performance)   |              |
| P1  | Загрузка страницы <100ms                               | ABS медленная, предусмотреть кэширование. Микросервисы должны взять часть функционала на себя. Разделить загрузку медленных данных (персональных ставок) и общего макета страницы - сначала макет и заглушки, а потом догрузка данных              |
| P2  | Система должна удерживать показатели быстродействия при пиковой загрузки. Для MVP 100 запросов\c                               |              |
| S   | Поддерживаемость (Supportability)  |              |
| S1  | Swagger документация и API для тестирования                                |              |
| S2  | UML C4-диаграммы архитектуры приложения и детализация новых сервисов                                 |              |
| S3  | CI\CD, Автотесты                              |              |
| +R  | + Ограничения (Restrictions)       |              |
| +R1 | .Net 4.5, MsSQL, Oracle PL\SQL, PHP                               |  Для внутренних данных микросервисов можно использовать "бесплатные" СУБД (postgre), В остальных случаях задействовать Oracle и MSSql и переиспользовать существующий в них функционал по созданию\обработки заявок           |
| +R2 | Шифрование TLS 1.2+                                | .Net 4.5 поддерживает, необходимо обновить ОС.             |
| +R3 | ABS не умеет в Kafka. Необходимо прокси или сервис-прослойку.                               | Для переиспользования функционала PL\SQl для MVP можно обращаться напрямую к БД            |
